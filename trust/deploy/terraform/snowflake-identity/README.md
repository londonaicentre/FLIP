# Snowflake identity tier (FLIP#1581, epic #1589)

The six `FLIP_<CODE>_*` roles, their hierarchy and the deploy `SERVICE` user. Nothing else: no
object that holds data, no privilege on one, no person user.

It is the first of three roots, each with its own state and its own role:

| Order | Root | Applied as | Creates |
| ----- | ---- | ---------- | ------- |
| 1 | here | the role that administers users (`USERADMIN`, or `ACCOUNTADMIN`) | roles, role hierarchy, deploy user |
| 2 | [`../snowflake-platform`](../snowflake-platform/README.md) | `ACCOUNTADMIN`, or the role that owns objects | account grants, egress integration, warehouse, logging objects |
| 3 | [`../snowflake`](../snowflake/README.md) | `FLIP_<CODE>_DEPLOY` | database, pools, repository, stages |

It is a root of its own because creating roles and users is a different job from owning objects,
and on an account that already holds other things those are different roles held by different
people. One root, one role, one session: any sign-in method works, a one-time passcode included.

## What it creates

With `trust_code = GSTT`:

| Object | Name | Holds |
| ------ | ---- | ----- |
| Workload role | `FLIP_GSTT_DEPLOY` | the five roles below; granted to `SYSADMIN` so object administrators can see the tree |
| Service role | `FLIP_GSTT_SVC` | `FLIP_GSTT_OMOP_READER` |
| OMOP roles | `FLIP_GSTT_OMOP_READER`, `FLIP_GSTT_OMOP_LOADER` | nothing here; the workload root grants on its tables |
| Observer | `FLIP_GSTT_OBSERVER` | nothing here; the platform root grants on the logs |
| Converter | `FLIP_GSTT_CONVERTER` | nothing here; the workload root grants on its procedures |
| Deploy user | `FLIP_GSTT_DEPLOY_USER` (`TYPE = SERVICE`, key pair, no password) | `FLIP_GSTT_DEPLOY` |

The roles are empty when this root has run. Every privilege is granted later, by the root that
owns the object.

## Usage

```bash
cd trust/deploy/terraform/snowflake-identity
cp terraform.tfvars.example terraform.development.tfvars   # gitignored; fill it in
make plan
make apply        # shows the plan and asks before creating anything
make test         # the credential-free pytest guards
make lint         # fmt, validate, tflint, checkov
```

Credentials come from the environment, as in the platform root
([Credentials](../snowflake-platform/README.md#credentials)). `identity_role` has no default: the
operator names it in the gitignored tfvars file.

If the plan fails at sign-in (no second factor enrolled, a passkey only, a token without a network
policy), see [Troubleshooting](../snowflake-platform/README.md#troubleshooting).

The deploy user's key pair is generated by whoever will run the workload root; only the public
half is an input here:

```bash
openssl genrsa 2048 | openssl pkcs8 -topk8 -v2 aes-256-cbc -out flip_deploy.p8
openssl rsa -in flip_deploy.p8 -pubout | grep -v -- '-----' | tr -d '\n'   # deploy_user_public_key
```

## Removing it

`make destroy` drops the roles and the user. Destroy the workload root and then the platform root
first: a role that still owns objects cannot be dropped.
