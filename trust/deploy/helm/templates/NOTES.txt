{{- if and .Values.omopDb.enabled .Values.omopDb.vocabLoad.enabled (not .Values.omopDb.vocabLoad.hostPath) }}

⚠️  OMOP core vocabulary was NOT loaded

    omopDb.vocabLoad.hostPath is empty, so the omop-vocab-load hook was skipped.

    The omop-db image and the seeded database are vocab-free by design: the
    licensed bundle (SNOMED CT / LOINC / Read v2 / dm+d) cannot be published,
    so this chart will not fetch it for you.

    Until it is loaded, cohort queries that join omop.concept return NOTHING —
    the stack looks healthy and silently matches no patients.

    Load it by:
      1. getting the bundle as a folder of CSVs — with access to the AI Centre
         bucket, from the repo root (your own AWS CLI profile):
             make -C trust/deploy/helm download-vocab
         otherwise an OHDSI Athena / NHS TRUD export;
      2. staging it onto the node:
             make -C trust/deploy/helm stage-vocab VOCAB_DIR=<folder> KUBE_CONTEXT=<ctx>
      3. setting omopDb.vocabLoad.hostPath (or the kit's OMOP_VOCAB_DIR) and
         re-running `helm upgrade`.

    See trust/deploy/helm/README.md → "OMOP core vocabulary".
{{- end }}
{{- if and .Values.flClient.enabled (not .Values.sharedImagesPvc.enabled) }}

⚠️  fl-client and imaging-api do NOT share an images volume

    sharedImagesPvc.enabled is false, so the `images` volume is a per-pod
    emptyDir: imaging-api "successfully" downloads studies into its own pod
    while the fl-client's copy of {{ .Values.flClient.imagesDir }}/{{ .Values.flClient.netId }}
    stays empty. Nothing errors — training just finds no data and dies with
    num_samples=0.

    For a functional FL trust, set sharedImagesPvc.enabled=true and re-run
    `helm upgrade`. The shipped default is ReadWriteOnce, which every storage
    class this chart is validated on provides; the chart then pins the fl-client
    and imaging-api to one node so the single-node mount that RWO implies is
    satisfied. Only move to an RWX-capable class if you need the two pods on
    different nodes; the chart drops that pin on ReadWriteMany.
{{- end }}
