# AGENTS.md — flip-ui

## Scope

Applies to the Vue frontend under `flip-ui/`.

## Service Overview

`flip-ui` is the Vite/Vue 3 frontend for researchers and administrators. It uses TypeScript, Pinia, Vue Router,
TailwindCSS, AWS Amplify/Cognito auth, Vitest, Cypress, and npm.

## Runtime Configuration

- Runtime config is read from `window.*` globals generated into `public/js/window.js`.
- `public/js/window.js` is generated by `scripts/generate-window-js.sh` and must not be committed.
- Local dev generation is handled by npm pre-hooks. Staging/prod deployment generation is handled by
  `deploy/providers/AWS make deploy-ui`.
- Do not reintroduce duplicated `VITE_` configuration for values that are intentionally runtime-driven.

## Commands

Run from `flip-ui/`:

```bash
npm install            # Install dependencies
npm run lint           # ESLint for Vue/TypeScript sources
npm run test:unit      # Vitest with coverage
npm run build          # Type check and Vite build
npm run build:deploy   # Deployment build used by AWS deploy-ui flow
npm run test:ci        # Cypress flow with dev server
make unit_test         # Dockerized unit tests through root compose
```

## Conventions

- Pages live in `src/pages/`; reusable components live in `src/partials/`.
- Stores live in `src/store/`; service clients live in `src/services/`; router/auth navigation logic lives in
  `src/router/` and `src/utils/auth.ts`.
- Keep auth flows explicit: Cognito challenge steps, MFA setup/verify state, and post-login hydration races should have
  focused tests.
- Prefer existing component patterns and Tailwind utility style already used in nearby files.
- When adding runtime dependencies imported by app code, put them in `dependencies`; keep type-only packages in
  `devDependencies`.
