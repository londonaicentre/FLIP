# This MAP is built on the CUDA-13 toolchain generation, which is what MONAI Deploy and Holoscan
# ship today. Every line below is load-bearing:
#   * torch from PyPI's default wheel line, which is cu130. That needs **NVIDIA driver >= 580** on
#     the packaging host and on every host that runs the MAP — the one hard prerequisite this
#     template adds. The alternative, staying on the cu128 index, means staying on torch 2.11.0
#     permanently: it is the last cu128 build PyTorch publishes.
#   * monai >= 1.6.0 — four high-severity advisories are patched only there, and it is what FLIP
#     trains with, so a directory bundle rebuilds its architecture under the same MONAI that
#     produced the weights. (The inherited monai<=1.5.0 also declared torch<2.7.0, and torch <2.7
#     has no sm_120, so a MAP built that way could not use a Blackwell GPU at all while
#     torch.cuda.is_available() still returned True.)
#   * monai-deploy-app-sdk 4.x, which tolerates holoscan.graphs' removal — 3.5.0 does
#     `from holoscan.graphs import *` and therefore needs holoscan 3.x.
#   * holoscan-cu13 4.2.0 to match. Package with holoscan-cli **4.2.0**: 4.3.0 replaced MAP
#     packaging with a source-project build system, and monai-deploy-app-sdk depends on
#     holoscan-cli unpinned, so an unconstrained install has no `holoscan package --models` at all.
torch==2.13.0
monai>=1.6.0
monai-deploy-app-sdk==4.0.0
holoscan-cu13==4.2.0
