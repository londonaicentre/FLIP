# flip-utils

The NVIDIA FLARE federated learning base library for the FLIP ecosystem. This project
provides pip-installable Python packages (`flip-utils`), reusable NVFLARE components,
Docker services for FL networks, and tutorial applications for medical imaging.

## Language

**Client API**:
The modern NVFlare API for client-side federated learning, using `flare.init()`,
`flare.receive()`, and `flare.send()` instead of the legacy Executor/Controller pattern.
_Avoid_: Executor, Controller (when referring to the old pattern)

**FedAvgRecipe**:
A PyTorch-specific recipe class (`nvflare.app_opt.pt.recipes.fedavg.FedAvgRecipe`) that
configures a complete FedAvg job with ScriptRunner, model persistor, and optional early
stopping — replacing manual `config.json` setup.
_Avoid_: config.json, ScatterAndGather

**FLUNet**:
A thin wrapper around `monai.networks.nets.UNet` that stores constructor parameters as
instance attributes so the PyTorch model serialiser can reconstruct it from a config dict.
_Avoid_: get_model() function, plain UNet (in job context)

**MonaiAlgo**:
A MONAI `fl.client` class that wraps MONAI bundle configs for federated learning.
Not used in FLIP tutorials — we prefer direct Client API control.
_Avoid_: Using this in tutorials (we bypass MONAI bundle config)

**SimEnv**:
The simulation execution environment (`nvflare.recipe.SimEnv`) that runs FedAvgRecipe
locally — used for integration tests and development.
_Avoid_: Direct `nvflare simulator` CLI

**FLIP()**:
The factory class (`flip.core.flip.FLIP`) that returns a `FLIPBase` implementation (Dev
or Prod) for accessing project data, the FLIP dataframe, and sending metrics to the
Central Hub.

**ScatterAndGather (deprecated)**:
Legacy NVFlare controller. Replaced by `FedAvgRecipe` + `fl.client` API.

## Relationships

- A **FedAvgRecipe** runs **client.py** (which uses the **Client API**) in a **SimEnv** (testing) or
  via `--export` + Docker compose (production)
- **client.py** uses `FLIP()` to load data before the FL loop, then trains **FLUNet** in the
  `receive → evaluate → train → send` cycle
- **Weight diff** (`TransferType.DIFF`) reduces bandwidth by sending only the model delta
  instead of full weights

## Example dialogue

> **Dev:** "Should I wrap our training in a MonaiAlgo or MonaiBundle?"
> **Domain expert:** "No — we don't use MONAI bundles. Write a `client.py` with the
> native Client API. Use `FLIP()` to get the dataframe, build your own DataLoaders
> from the transforms in `transforms.py`, and call `flare.receive()` / `flare.send()`
> directly."

## Flagged ambiguities

- "config.json" was used to mean both the NVFlare job config and the app
  hyperparameter file — resolved: hyperparameters are CLI arguments now, job config is
  generated by `FedAvgRecipe`
- "Executor" was used to mean both `RUN_TRAINER` (our custom executor) and any NVFlare
  executor — resolved: we use the Client API now, no custom executors
